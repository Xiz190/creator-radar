## 二、获取方式与合规声明

- **公开 RSS**：媒体站为 SEO 主动开放的订阅源，标准、合法、稳定。
- **服务端渲染 HTML（SSR）**：官方博客的列表页由服务器直接渲染，可静态解析。
- **公开 API**：机构站对外开放的列表接口（如国家艺术基金）。
- **不采集**：任何需要登录的平台（公众号、微博等）、需绕过反爬的站点（Midjourney/Ideogram/Leonardo 等强反爬源已主动排除）、任何私密/个人数据。

## 四、已知局限 & 设计取舍

> **源筛选原则：宁可少而真，不要多而空。** 只收录**正文可干净抽取**的源；对正文不可抽取的源（SPA 空壳、扫描件 PDF、需登录 / 强反爬），宁可**放弃收录**也不让空壳与乱码进入数据。情报的价值在「**对创作者意味着什么**」的解读层，不在原始条数——因此本站刻意**不追求源数量**，而追求每条都真实、可读、可解读。这与产品内的诚实规则（信息不足时提示"点原文确认"、绝不臆造）是**同一套原则在数据层的延伸**。

### 1. 主动排除 CAPA（中国演出行业协会）——数据源验收的踩坑复盘
- **问题**：CAPA 官网为**单页应用（SPA）**，正文由**客户端渲染（CSR）**动态生成，静态请求仅返回空壳；详情链接为 **hash 路由死链**（`#/` 始终跳转主页）。其列表 API 仅返回**元数据（标题/日期）**，**内容主体与可访问原文链接缺失**，呈现「列表可抓、详情不可抓」的典型困境，**内容提取失败率 100%**。
- **早期偏差**：初次接入时，因列表 API 能返回标题/日期即判定"可用"，**未验证端到端可用性（详情链接 + 正文）**。
- **详情两种形态都不可抽取**（实测复核）：① 站内 `news/{id}` 页是 Vue SPA 空壳，正文提取 0 段；② 部分详情为附件 PDF，且是**扫描件图片（无文字层）**，即便不谈静态抓取、连 OCR 前都是空。
- **核心栏目已停更**：最对口创作者的「音乐人才扶持」栏目内容停在 **2021–2022**，无新增机会。
- **顺带修复一个假阳性 bug**：扫描件 PDF 的二进制字节曾被正文质量评估误判为 `high`（把字节当成 20 段"正文"）。已在详情抓取层加**二进制文档检测短路**（Content-Type + `%PDF` 魔数 + 乱码占比三重识别），命中即归为附件、正文判 `empty`，杜绝二进制乱码污染数据。
- **纠正**：通过链接可达性与正文质量实测发现问题，**主动排除**该源（仅在必要时保留标题作线索，不作正文展示）。
- **教训**：数据源验收应看**端到端可用性**（列表 + 详情 + 链接 + 正文可读都通），而非仅"列表能否拿到"。

### 2. 国内 AI 创作机会源稀缺
- 国内相关机会源多为政务式 SPA 站，普遍存在上述"难以结构化"问题。
- 应对：现阶段以官方工具源 + 国际媒体为主。**不为凑数而扩源**（见上"源筛选原则"）——仅当出现正文可干净抽取的国内机会源时才按需补充，且以"补齐特定视角缺口"为准，而非追求覆盖广度。

### 3. 分类 / 体裁的准确率天花板
- 体裁分类基于关键词匹配，对无明显体裁词的标题会归入"其他"（存在覆盖率上限）。
- 重要性分级基于**关键词信号打分**：对标题/正文命中的关键词按权重累加（工具名、发布动词、版本号等，**标题命中加权更高**），再按阈值分层为 **核心 / 重点 / 中等 / 普通**；**LLM 仅负责生成每条的"创作者视角"解读文字，不参与定级**。将评级交由 LLM 语义判断是 roadmap（见 §六.3）。
- 未来可将分类/体裁同样交由 LLM 语义判断，进一步提升准确率。

### 4. 地区维度弱化
- "国内/全球"维度对以国际工具为主的创作者情报台意义有限（国内源稀薄），后续考虑改为"工具官方 / 行业媒体 / 创作机会"的来源类型维度。

### 5. 中文旗舰生成工具（可灵 Kling / 即梦 Dreamina）无官方可爬发版流 —— 主动取舍
- **诉求**：作为"创作者雷达"，理应覆盖当下最主流的中文视频/图像生成工具（可灵、即梦）的**重大版本更新**。
- **实测结论（官方直连不可行）**：
  - 可灵 `klingai.com/release-notes` 实为**营销页**，不含带日期的更新日志（无 `releaseNote / changelog / publishTime` 字段、页面内 0 个日期），仅有一行 `modelUpgradeNotice` 营销字符串；页面暴露的接口全是**产品功能 API**（文生视频 / 图生视频等），**无 news / release 内容接口**——即便逆向也拿不到"带日期的发版历史"。
  - 即梦 / Dreamina（`dreamina.capcut.com`）为**纯 SPA 空壳**，可见文本仅为样式代码，0 个 release / date 字段。
  - 二者均**无 RSS、无公开 news API、无结构化 changelog**，属"只有营销页 + 功能接口"的形态。
- **设计取舍（不硬接）**：直连这类站点需**逆向 + 高维护成本 + 极易随改版失效**，且**根本拿不到干净的发版流**，投入产出比极低。因此**刻意不收录其官方源**（延续本节开头"宁可少而真"的源筛选原则），改由**权威中文 AI 媒体（量子位等已收录源）**覆盖其重大发布。
- **配套机制（覆盖靠媒体、显著性靠排序）**：重要性排序加入"**发布信号识别**"——识别标题中的「工具名 × 发布动词 × 版本号」（如 `launches / 发布 / v6`），使旗舰工具的**重大版本更新经媒体报道进入后能自动升至"重点 / 核心"档**，不被日常资讯淹没。
- **诚实边界**：对可灵/即梦更新因此存在**时效滞后**（依赖媒体报道节奏）与**颗粒度限制**（非逐条官方 changelog）。这是**主动技术判断下的已知取舍**，而非疏漏。

## 五、技术术语表

| 术语 | 含义 |
|---|---|
| **SPA（单页应用）** | 整站靠一个页面 + JS 动态切换内容，直接访问深层 URL 常打不开 |
| **CSR（客户端渲染）** | 内容由浏览器执行 JS 后生成，服务器返回的原始 HTML 为空壳，静态抓取拿不到 |
| **死链（dead link）** | 链接指向的页面无有效内容 |
| **元数据（metadata）** | 标题/日期等描述性信息，区别于"内容主体（正文）" |
| **端到端可用性** | 整条链路（列表 → 详情 → 链接）能否真正使用 |
