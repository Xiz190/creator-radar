# 每日日报邮件：怎么接的、怎么改、怎么排查

每天北京时间 08:40，系统把近 24 小时的重点条目整理成一封邮件，发到作者的邮箱。
这份文档说明它由哪几部分组成、配置放在哪里、以后要改什么去哪里改。

## 一句话流程

GitHub Actions 定时运行 → 脚本从数据库取近 24 小时的条目 → 用共用模板生成邮件 → 通过 Resend 发出。

网站本身**不发信**：线上站点（Vercel）上没有 Resend 的密钥，发信只在 GitHub Actions 里发生。

## 组成部分

| 作用 | 位置 |
|---|---|
| 定时任务 | `.github/workflows/daily-summary.yml`（UTC 00:40 = 北京 08:40；也能手动触发） |
| 发信脚本 | `scripts/send-daily-summary.ts` |
| 取数（近 24 小时、按重要度排序、带中英创作者视角） | `src/lib/monitor/db/digest.ts` |
| 邮件模板（中英双语，标题和链接先转义） | `src/lib/monitor/digest-email.ts`（测试：同目录 `digest-email.test.ts`） |
| 网站上的预览页 | `/digest`（作者专用），调 `src/app/api/monitor/digest/route.ts`，和发出去的邮件同一份取数、同一个模板 |

## 配置放在哪里

全部在 GitHub 仓库的 **Settings → Secrets and variables → Actions**：

| 名字 | 是什么 | 谁设的 |
|---|---|---|
| `RESEND_API_KEY` | Resend 的 API key（`re_` 开头） | 在 Resend 后台 API Keys 页创建 |
| `DAILY_SUMMARY_EMAIL` | 收件地址，多个用英文逗号分隔 | 仓库设置里手动填 |
| `DATABASE_URL` | 线上数据库，抓取任务也在用 | 已有 |

可选：在 workflow 的 `env` 里加 `DAILY_SUMMARY_LANG: zh` 可以改发中文版，默认英文。

本地 `.env.local` **不需要** Resend 的 key；本地只用来试跑（见下文）。

## 常见操作

**手动发一封**：GitHub 仓库 → Actions → 「每日日报邮件」→ Run workflow。

**本地试跑、不真发**：

```bash
DRY_RUN=1 npx tsx --env-file=.env.local scripts/send-daily-summary.ts
```

会打印邮件主题和纯文本内容，不调用 Resend。

**换收件邮箱**：改 GitHub secret `DAILY_SUMMARY_EMAIL`。
注意：没有自己的域名时，Resend 只能用公共发件地址 `onboarding@resend.dev`，**而且只能发到注册 Resend 时用的那个邮箱**。
想发到别的邮箱或多个邮箱，需要在 Resend 后台验证一个自己的域名，再把脚本里的 `from` 改成该域名下的地址。

**改发送时间**：改 `daily-summary.yml` 里的 `cron`（用 UTC 时间）。

**改邮件长什么样**：改 `digest-email.ts`，然后打开 `/digest` 预览，跑 `npx vitest run src/lib/monitor/digest-email.test.ts`。

**改选哪些条目**：改 `db/digest.ts` 里的查询（时间窗口、条数上限、重要度门槛）。

## 排查

- **没收到**：先看 Actions 里那次运行是不是绿的。红的话日志里会有 `[daily-summary] Resend 返回 …` 或 `缺少 RESEND_API_KEY`。
- **运行是绿的但没收到**：去 Gmail 的「推广」和「垃圾邮件」里找；第一次收到后点「不是垃圾邮件」。也可以在 Resend 后台 Emails 页看投递状态。
- **内容是空的**：近 24 小时没有新的重点条目时会发一封说明「没有新内容」的邮件。如果连续几天都空，先检查抓取任务（「定时抓取」workflow）是不是在正常跑。

## 公开仓库

`publish/exclude.txt` 里排除了 `daily-summary.yml`：公开仓库没有这些密钥，定时任务每天都会失败。
脚本、模板和预览页会公开，定时任务只在私有工作仓里运行，和抓取任务 `crawl.yml` 的处理方式一样。
