# Creator Radar

**English** · [中文](README.zh-CN.md)

> An AI news radar for independent musicians. It pulls AI tool and industry updates from official channels and trade media on a schedule, and tells you what each one means for making music or MVs.

**Live demo**: <https://creator-radar-xiz.vercel.app> (demo mode: visitors can browse, search and use the Q&A assistant; editing and the admin pages are author-only). Mobile companion: [/m](https://creator-radar-xiz.vercel.app/m).

## The problem

AI and the internet move fast. Something new shows up every day, and we've been past information overload for a while.

But the real problem for independent creators isn't a lack of information. It's this: Suno ships a new version, Krea drops a model, Runway changes its terms. **What does any of that have to do with the music or MV I'm making?**

Creator Radar semi-automates an intelligence workflow (find, verify, connect, analyze) and adds one layer generic aggregators don't have: **a creator's point of view**.

Every update comes with a short take written from where you stand, not just a headline. Here's a real one from the live site:

> ElevenLabs unveils 'Music v2.5' – but UMG wasn't involved  
> **Creator lens:** The UMG carve-out matters more than the model: your vocals and mixes aren't the licensed part, so read the terms before you upload.

In short, it watches AI news for you and turns it into "here's what this means for your music and your MVs."

- **You don't have to chase it.** Crawling runs on a schedule you can set. Locally it can run as often as you like; the live demo runs on a free hosting tier, so it updates every 6 hours.
- **You don't have to fact-check the source.** It only pulls from AI tools' official channels and a fixed set of trade publications, with the source on every item. That keeps out the AI-generated, garbled or unofficial versions floating around online.
- **It gives you a first read.** Each item gets a one-line creator lens, generated by an LLM following the lens settings. It has a stance and a human voice, which makes it a quick reference for your own judgment, not the final word.

## What makes it different: the creator lens

This is the heart of the project. It isn't a keyword classifier. It's an **LLM layer that writes from a creator's perspective**:

- **A three-part knowledge base** (`knowledge/lens/`). You tune the lens by editing text files, not code ([how](#make-the-lens-yours)):
  - `persona.md` · **Personal**: who you are and how you talk (one per creator)
  - `objective.md` · **Objective**: the analysis framework plus factual knowledge, each with a source and date (shareable)
  - `examples.md` · **Examples**: lens lines you've approved. The more you add, the more consistent the voice gets
- **Objective and personal layers kept apart**: everyone can share one factual base while keeping their own point of view, so each person effectively has their own knowledge base
- **Value rating**: the LLM also rates each update as high, medium or low value for creators, which drives sorting and the "high priority" flag

## Real data

**15 active sources, every item with a creator lens.** The live site grows every 6 hours, and everything comes from public APIs, public RSS feeds or public web pages. Live counts: [`/api/monitor/corpus-stats`](https://creator-radar-xiz.vercel.app/api/monitor/corpus-stats)

| Type | Sources |
|---|---|
| Official AI tool channels | Suno · ElevenLabs · Pika · Krea · Luma · Runway · Mubert · Splice · Stability AI |
| Trade media | CDM · Synthtopia · Music Ally · PetaPixel · QbitAI (量子位) |
| Creator opportunities | China National Arts Fund (国家艺术基金) |

**Compliance**: no logins, no getting around anti-bot protection, no private data. Sources behind heavy anti-bot walls (Midjourney, Ideogram, Leonardo) and a dead single-page-app source (CAPA) were deliberately left out. See [`docs/数据源说明-已知局限.md`](docs/数据源说明-已知局限.md) (in Chinese) for details.

## Architecture

```
Data layer (list + runner crawler architecture)
  ├─ Official blogs / RSS / sitemaps / public APIs  → list crawling
  └─ Detail crawling (body extraction, filters out comments and most page boilerplate)
        ↓
Lens layer (creator lens + three-part knowledge base + DeepSeek)
  ├─ One-line creator lens
  └─ Value rating (high / medium / low)
        ↓
Presentation layer (feed / detail page / signal radar)
  └─ Each update = title + source + creator lens
```

## How this was built

I'm an ICAM (Interdisciplinary Computing and the Arts) student at UC San Diego, not a software engineer by training. This project grew out of a small tool I built for myself during an internship (the full story is in [Policy Radar](https://github.com/Xiz190/policy-radar)). I later realized it wasn't really about policy. It was about watching the sources I care about and telling me what changed and why it matters. So I rebuilt it from scratch for my own field: music and AI-assisted creation.

**What I was responsible for**:
- Framing the problem and choosing the domain
- Choosing sources, figuring out which subpages could be crawled reliably, and dropping the ones that couldn't
- The category system and the creator-lens design (the three-part knowledge base and value rating), including writing my own stance and background into the lens
- **Related updates**: a lot of sites build on or follow up on each other, so every item links to related items in three ways: same topic, same source, and cross-references
- User experience, front-end design and interaction, including the mobile companion's iterations and the features I cut to keep the scope manageable
- Checking the data: I regularly open the original pages to compare them with what the crawler pulled. That's how I found leftover interface text like "See all", "Show details" and "Discussion" mixed into article bodies. Most of it is filtered out now, but a few sites still let some through.

**What AI did**: most of the code was written by Claude Code (Anthropic) to my specifications. I reviewed the changes, ran and checked the tests, and decided what shipped.

**Next**: pushing updates to WeChat and Feishu (Lark), and connecting AI agents like OpenClaw so they can analyze the feed as a whole.

## Quick start

You'll need Node.js, PostgreSQL 16, and an API key for any OpenAI-compatible LLM (DeepSeek, OpenAI, etc.).

```bash
npm install
cp .env.local.example .env.local                  # fill in DATABASE_URL and LLM_* (see below)

createdb creator_radar                            # any name, just match DATABASE_URL
psql -d creator_radar -f schema.sql               # create tables
psql -d creator_radar -f creator-seed.sql         # add the 15 sources and keywords

npx tsx --env-file=.env.local scripts/crawl.ts    # one crawl, lens lines generated automatically
npm run dev                                       # open http://localhost:3000
```

The three LLM lines in `.env.local` are commented out by default. Uncomment and fill them in. With DeepSeek, for example:

```bash
LLM_API_KEY=sk-your-key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

- LLM APIs are usually **pay-as-you-go**, and this runs on your own key. Each item gets two calls (Chinese and English). That's cheap per item, but keep an eye on your balance.
- Without a key, crawling and browsing still work. You just won't get the creator-lens line.
- `init-data.sql` is seed data left over from the earlier government-policy version. You **don't need** it here; `creator-seed.sql` covers everything.
- There are three env templates: `.env.local.example` for local development, `.env.docker.example` for Docker, and `.env.example`, a shorter subset of the first.
- **Demo mode**: the live demo is read-only for visitors via `PUBLIC_DEMO=1` plus `ADMIN_TOKEN`. The author unlocks everything at `/unlock`. Section 3 of `.env.local.example` explains how to turn it on for your own deployment. Leave it off for local development.

Other commands: `npm run build` (production build), `npm run test` (unit tests).

## Make the lens yours

The `knowledge/lens/persona.md` in this repo describes a **fictional example creator**, not the author. To get takes written from your point of view:

**1. Swap in your identity.** Edit `knowledge/lens/persona.md` (Chinese lens) and `persona.en.md` (English lens). Replace the identity section with you: what you make, what tools you use, what you care about. Keep the tone rules and the "every line must be useful" rules. They're what keep the lines short and actually helpful.

**2. (Optional) Add examples.** Put a few takes you like into `examples.md` / `examples.en.md`. More examples, steadier voice. `objective.md` is the shared analysis framework and facts, and usually doesn't need changes.

**3. No code changes.** On every run, `src/lib/monitor/creator-lens.ts` reads these files as the system prompt and sends them to the LLM along with the item's headline and the first 1,500 characters of its body. The line that comes back is saved to the database. The frontend just displays it.

**4. New items pick up the new lens automatically.** Every run of `scripts/crawl.ts` fills in lens lines for new items afterward (up to 40 per language per run; the rest roll over to the next run). After your first crawl there may be a lot, so you can fill them all at once:

```bash
npx tsx --env-file=.env.local scripts/gen-lens.ts all      # Chinese
npx tsx --env-file=.env.local scripts/gen-lens-en.ts all   # English
```

**5. Old items are not rewritten.** Backfill only touches items that don't have a lens yet. Existing lines, including ones you edited by hand, are never overwritten. To rewrite old items with your new lens, clear them first, then run the two commands from step 4:

```sql
-- ⚠️ Wipes every existing lens line, including ones you hand-tuned. Regenerating calls the LLM again.
update monitor_items set creator_lens = null, creator_lens_en = null
where list_published_at >= '2026-01-01';
```

**6. Scheduling is up to you.** This public repo ships without a scheduled job. The live demo's scheduled crawl runs from the author's private deployment, since it needs database credentials and API keys, so it isn't included here. To keep it updating, run `scripts/crawl.ts` on a timer (cron, GitHub Actions, etc.) with `DATABASE_URL` and `LLM_*` set in that environment. If your crawler runs from GitHub, **commit and push** your persona changes so it picks up the new files.
